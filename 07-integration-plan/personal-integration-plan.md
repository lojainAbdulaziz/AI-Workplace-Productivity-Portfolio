# Personal Integration Plan

## Role

**Project Coordinator**

## Purpose

The goal of this integration plan is to use Generative AI as a productivity support tool for recurring project-coordination tasks while keeping human verification and decision-making in place.

---

# Task 1 — Draft Internal Project Updates

## Recurring Task

Prepare concise internal updates about project status, risks, and changes.

## Expected Benefit

Reduce the time needed to organize information and create clear professional updates.

## Preferred Prompt / Workflow

Use the workflow:

**Context → Audience → Confirmed Facts → Required Actions → Output Format → Verification**

Prompt pattern:

> Act as a project coordinator. Using only the confirmed information provided, draft a concise internal project update. Separate confirmed facts from information still pending. Do not invent dates, owners, impacts, or commitments. Use [Not Specified] when information is unavailable.

## Risk / Verification Requirement

Verify all dates, figures, names, project impacts, and commitments against the original source before sending.

## Frequency

As needed, especially when there is a significant project update or change.

## Success Indicator

The final update is accurate, concise, easy to understand, and requires minimal manual rewriting before human approval.

---

# Task 2 — Convert Meeting Notes into Action Items

## Recurring Task

Turn unstructured meeting notes into a clear action-item list.

## Expected Benefit

Make responsibilities, deadlines, priorities, and status easier to track.

## Preferred Prompt / Workflow

Use:

**Input → Extract → Structure → Human Review**

Prompt pattern:

> Act as a project coordinator. Extract only the action items supported by the meeting notes and organize them into the following table: Action Item | Owner | Deadline | Priority | Status. Do not invent missing owners or deadlines. Use [Not Specified] when information is unavailable.

## Risk / Verification Requirement

Compare every action item with the original meeting notes. Do not assign an owner or deadline unless it was actually stated or formally confirmed.

## Frequency

After each relevant project meeting.

## Success Indicator

Meeting notes are converted into an accurate action-item table that can be reviewed and used by the project team.

---

# Task 3 — Create Project Recovery Plans

## Recurring Task

Structure recovery options when a project faces a delay, dependency issue, or operational risk.

## Expected Benefit

Provide a clear starting point for organizing recovery activities and identifying dependencies.

## Preferred Prompt / Workflow

Use:

**Goal → Mechanisms → Phases → Tasks → Dependencies → Decision Points**

Prompt pattern:

> Act as a project coordinator. Create a concise recovery plan for the stated project issue. Break the goal into mechanisms, phases, and actionable tasks. Identify dependencies and decision points. Do not invent deadlines, owners, or commitments.

## Risk / Verification Requirement

Check that proposed actions are realistic and that the plan does not present AI-generated suggestions as approved decisions.

## Frequency

When a significant project risk or delay occurs.

## Success Indicator

The recovery plan clearly shows the goal, phases, tasks, dependencies, and decisions required from the project team.

---

# Task 4 — Prepare Management Status Briefs

## Recurring Task

Prepare concise summaries for management or project leadership.

## Expected Benefit

Make important project information easier to review and support faster decision-making.

## Preferred Prompt / Workflow

Use:

**Status → Confirmed Facts → Impact → Risk → Actions → Decision Required → Pending Information**

Prompt pattern:

> Act as a project coordinator preparing a management status brief. Summarize only confirmed information, identify key risks and actions, and clearly state information that is still pending. Do not invent figures, dates, causes, owners, or decisions.

## Risk / Verification Requirement

Verify important facts and ensure that the brief distinguishes confirmed information from potential risks or recommendations.

## Frequency

Weekly or when a significant project issue requires management attention.

## Success Indicator

Management receives a concise and accurate brief that clearly identifies the current status, risks, actions, and decisions required.

---

# Standard AI Workflow

For recurring tasks, I will use the following workflow:

**1. Define the task**  
Clarify what needs to be produced.

**2. Provide relevant context**  
Give only the information required for the task.

**3. Specify the output**  
Define the required structure, audience, and tone.

**4. Generate**  
Use AI to create a draft or structured result.

**5. Verify**  
Check facts, dates, names, figures, uncertainty, and missing information.

**6. Refine**  
Improve clarity and tone while preserving accuracy.

**7. Human Sign-off**  
Review and approve the final output before it is used.

---

# Success Criteria

My AI use will be considered successful when it:

- Reduces time spent on repetitive drafting and structuring tasks.
- Produces clearer and more organized workplace outputs.
- Helps identify missing information and follow-up actions.
- Does not replace human judgment or approval.
- Maintains accuracy and responsible handling of workplace information.
